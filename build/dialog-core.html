Terminal lookup
Typing ?dwell or ??G1 X10 F500 opens documentation instead of sending the text to the controller; ?? alone opens this reference unfiltered. A bare ? (status query) is never intercepted. On ncSender 2.0.191 and later, other commands keep flowing while the dialog is open; on older versions it pauses command streaming until closed, so avoid lookups mid-job there.

About this reference

Sources. The documentation in this plugin is compiled from:

  • Sienci Labs SLB/SLB‑EXT firmware documentation — the official settings tables, including SLB‑EXT factory defaults and Sienci’s “unused”/“advanced” notes.
  • grblHAL core source — the canonical setting registry and descriptions for mainline (Main_grblHAL) builds, including settings the Sienci tables don’t cover and the current numbering (e.g. laser XY offset at $770/$771, formerly $741/$742 on SLB 5.0.x firmware).
  • grblHAL community docs — the complete G‑code and M‑code reference the command entries are based on.
  • ncSender — the plugin API, and the /api/firmware endpoint (which controller is connected, plus ncSender’s cache of its own $ES/$$ settings list) that powers the live “on this controller” check.
  • OctoPrint Marlin G‑code Documentation — the plugin that inspired this one.
  • Rapid Change ATC, Manual Tool Changer, Pneumatic ATC, AutoDustboot and Dust Docker plugin repositories — the source for the commands documented under Plugin codes ($TLS, $SLOT<n>, $POCKET1, $PROBE, $MEASURE_TLO, $ADB_…, the Dust Docker macros).
  • Grbl 1.1 wiki, the FluidNC source and ncSender’s Grbl/FluidNC translators — which codes run on each controller.
  • Sienci ATCi plugin — M960 and the keepout settings $683–$687.

Which controllers this applies to. ncSender drives grblHAL, classic Grbl 1.1 and FluidNC. The entries are written for grblHAL; when ncSender is connected the reference knows which one you have, marks codes it can’t run “not on this controller”, and every G/M/$ entry shows how it fares on all three:

  • Sienci SLB / SLB‑EXT (grblHAL) — fully covered. Defaults are labeled “SLB‑EXT default”, Sienci‑specific settings (button macros $450s, ring/rail LEDs $664/$665, spindle slots $511+, ATCi keepout $683–$687) are included, and entries note where Main_grblHAL renumbered older SLB 5.0.x settings.
  • Other grblHAL boards — core G/M‑codes and settings apply as documented; Sienci‑specific entries are simply flagged “not on this controller”, since every grblHAL build only has the settings its features compile in.
  • Classic Grbl 1.1 — ncSender translates for it: it works out expressions, parameters and o‑word IF/ELSE itself, turns M6 into a “load tool” pause, and stops lines Grbl can’t run (M62–M68 I/O, G43 H, G59.1–59.3, G65, override control, loops) with an explanation. Lines are limited to 79 characters. Only $0–$132 exist, and a few (like $4, $5, $10, $22, $32) are simpler than on grblHAL — their entries say how.
  • FluidNC — runs most grblHAL G‑code as written, including expressions, o‑word flow control, M62–M68 I/O (with pins set up in config.yaml) and M70–M73. No canned cycles, tool table or G65. Machine setup lives in config.yaml: the numbered settings ncSender sees are read‑only copies, and their entries name the config.yaml key to change. FluidNC’s own $ commands ($CD, $SS, $LocalFS/… …) are under $ Commands.

The live check reads ncSender’s cached copy of your controller’s settings (from $ES/$$). After flashing new firmware, refresh ncSender’s Firmware tab once so the cache re‑reads them; this reference picks it up the next time it opens.
